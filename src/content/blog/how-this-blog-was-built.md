这个博客从零到上线，没有租服务器，没有数据库，总成本为零。这篇记录一下整个过程。

## 技术选型

调研了 2026 年主流的静态站点生成器之后，最终选择了 **Astro**：

| 方案 | 构建速度 | Markdown 支持 | 结论 |
| --- | --- | --- | --- |
| Astro | 快 | 最好 | ✅ 选定 |
| Hugo | 最快 | 一般 | 模板语法学习成本高 |
| Jekyll | 慢 | 一般 | GitHub 原生但生态停滞 |

理由很简单：博客的核心是文字，Astro 对 Markdown 的一等支持让它写文章像记笔记一样简单——新文章就是一个 `.md` 文件，推到 GitHub 就自动上线。

## 设计：苹果风

没有用任何现成主题，而是按照 Apple 设计语言的三个原则从零手写：

- **清晰**：内容为王，界面隐身
- **谦逊**：装饰永远服务于内容，从不抢戏
- **层次**：留白、字重、灰度制造层级，而不是靠边框和阴影

几个关键细节：

```css
/* 苹果系统字体栈，非苹果设备自动回退 */
font-family: -apple-system, BlinkMacSystemFont,
  "SF Pro Display", "PingFang SC", "Microsoft YaHei", sans-serif;

/* 正文 17px，行高 1.47 —— 苹果阅读体验的基石 */
font-size: 17px;
line-height: 1.47;
```

配色也完全取自苹果：近黑 `#1d1d1f`、次要灰 `#86868b`、表面灰 `#f5f5f7`、点缀蓝 `#0071e3`，外加跟随系统的明暗双主题。

## 部署：GitHub Pages

全流程自动化：

1. 代码推送到 `main` 分支
2. GitHub Actions 自动构建
3. 产物自动部署到 Pages

于是整个「写作—发布」流程只剩两步：写好 Markdown → `git push`。

## 你也能拥有一个

所有代码都是开源的。如果你想搭一个一样的博客，克隆仓库、改个名字、删掉我的文章、写你自己的——半小时以内的事。
